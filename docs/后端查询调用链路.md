# 后端查询调用链路文档

**版本**：1.0
**日期**：2026-05-06
**目的**：详细说明后端 SQL 查询（特别是 SELECT）的完整调用链路，供前后端团队理解。

---

## 1. 概述

前端（CLI 或 Qt）通过 `DBEngine::execute()` 提交 SQL 字符串，后端完成 **词法分析 → 语法分析 → 执行 → 返回结果** 的全流程。

```
用户输入 SQL
    ↓
DBEngine::execute(sql, session)
    ↓
Lexer::tokenize(sql)        # 词法分析：SQL → Token 流
    ↓
Parser::parse(tokens)       # 语法分析：Token 流 → AST
    ↓
Executor::execute(ast, session)  # 执行：AST → QueryResult
    ↓
返回 QueryResult
```

## 2. 模块职责

### 2.1 DBEngine（入口）
- **文件**：`src/engine/DBEngine.h` / `.cpp`
- **职责**：
  - 对外唯一接口 `execute(sql, session)`
  - 调用 Lexer、Parser、Executor 完成 SQL 执行
  - 捕获异常并转换为 `QueryResult::ERROR`

### 2.2 Lexer（词法分析）
- **文件**：`src/engine/lexer/Lexer.h` / `.cpp`
- **职责**：
  - 将 SQL 字符串分解为 Token 流
  - 识别关键字（`SELECT`, `FROM`, `WHERE` 等）、标识符、字面量、运算符
  - 处理字符串字面量和注释

### 2.3 Parser（语法分析）
- **文件**：`src/engine/parser/Parser.h` / `.cpp`
- **职责**：
  - 根据 Token 流构建抽象语法树（AST）
  - 递归下降解析器
  - 解析 SELECT 的多表 FROM、WHERE、ORDER BY 等子句
  - 支持 qualified 列名（`table.column`）和表别名

**重要函数**：
- `parseSelect()`：解析 SELECT 语句
  - 解析 `SELECT` 列列表（支持 `*`、`table.column`、聚合函数）
  - 解析 `FROM table1 alias1, table2 alias2, ...`（多表支持）
  - 解析 `WHERE` 条件（支持列到列比较）
  - 解析 `ORDER BY`、`GROUP BY`、`HAVING`、`LIMIT`、`OFFSET`
- `parseWhereExpr()`：解析 WHERE 表达式
  - 支持逻辑运算符（`AND`, `OR`, `NOT`）
  - 支持比较运算符（`=`, `!=`, `<`, `<=`, `>`, `>=`）
  - 支持 `IN`, `LIKE`, `BETWEEN`, `IS NULL`, `IS NOT NULL`
  - **新增**：支持右侧为列引用（column-to-column 比较）

### 2.4 AST（抽象语法树）
- **文件**：`src/engine/parser/AST.h`
- **职责**：定义所有 SQL 语句的结构化表示

**重要结构**：
- `SelectNode`：SELECT 语句节点
  - `fromTables`：多表列表（`vector<TableRef>`），每个 `TableRef` 包含 database、table、alias
  - `columns`：SELECT 列列表（支持 wildcard、column_ref、aggregate）
  - `where`：WHERE 条件表达式树
  - `orderBy`：ORDER BY 列表（支持 qualified 列名）
  - `groupBy`、`having`、`limit`、`offset`、`distinct`
- `WhereExpr`：WHERE 表达式节点
  - `kind`：COMPARISON / LOGICAL / COLUMN_REF / LITERAL
  - `tableAlias` + `columnName`：支持 qualified 列引用
  - `left` / `right`：子表达式（右侧可以是列引用或字面量）
- `TableRef`：表引用结构
  - `database`、`table`、`alias`

### 2.5 Executor（执行器）
- **文件**：`src/engine/executor/Executor.h` / `.cpp`
- **职责**：
  - 根据 AST 类型分发执行
  - 调用底层存储模块（TableManager、RecordManager、IndexManager 等）
  - 权限检查、完整性约束验证
  - 返回 QueryResult

**SELECT 执行流程**（`execSelect`）：

1. **多表扫描**：
   - 遍历 `fromTables`，加载每个表的 schema 和所有行
   - 检查每个表的 SELECT 权限

2. **构建笛卡尔积**（递归）：
   - 递归函数遍历所有表，生成所有行组合
   - 为每个组合创建 `map<string, FieldValue>`，键包括：
     - Qualified keys：`alias.column` 或 `table.column`
- Unqualified keys：`column`（仅当没有歧义时）。SELECT / ORDER BY 中遇到重复裸列名会返回明确错误，要求使用 `alias.column`。

3. **WHERE 过滤**：
   - 对每个行组合调用 `ExprEvaluator::evaluate()`
   - 只保留满足 WHERE 条件的行

4. **聚合/GROUP BY**：
   - 如果有聚合函数或 GROUP BY，按分组计算聚合值
   - 应用 HAVING 条件过滤分组

5. **ORDER BY 排序**：
   - 根据 ORDER BY 列对结果排序
   - 支持 qualified 列名查找

6. **LIMIT / OFFSET 分页**：
   - 应用分页限制

7. **投影输出**：
   - 根据 SELECT 列列表提取字段值
   - Wildcard (`*`) 时输出所有表的所有列（qualified 列名）
   - 应用 DISTINCT 去重

8. **返回 QueryResult**：
   - `columns`：列元信息（名称、类型）
   - `rows`：结果行数据

### 2.6 ExprEvaluator（表达式求值）
- **文件**：`src/engine/executor/ExprEvaluator.h` / `.cpp`
- **职责**：
  - 对单条记录求值 WHERE 表达式
  - 支持 qualified 列查找

**重要函数**：
- `evaluate(expr, row)`：递归求值表达式
  - COMPARISON：比较运算
  - LOGICAL：逻辑运算（AND / OR / NOT）
  - COLUMN_REF：列引用
  - LITERAL：字面量
- `lookupColumn(tableAlias, columnName, row)`：**新增**
  - 优先查找 qualified key（`tableAlias.columnName`）
  - 其次查找 unqualified key（`columnName`）
  - 如果在多个表中找到同名列，返回 NULL（歧义）

## 3. 多表查询示例调用流程

### 用户输入
```sql
SELECT u.name, o.amount
FROM users u, orders o
WHERE u.id = o.user_id AND o.amount > 100
ORDER BY o.amount DESC;
```

### 调用链

1. **DBEngine::execute()**
   - 输入：SQL 字符串 + Session
   - 调用 `Lexer::tokenize()`

2. **Lexer::tokenize()**
   - 输出：Token 流
     ```
     [SELECT, IDENTIFIER(u), DOT, IDENTIFIER(name), COMMA,
      IDENTIFIER(o), DOT, IDENTIFIER(amount), FROM,
      IDENTIFIER(users), IDENTIFIER(u), COMMA, ...]
     ```

3. **Parser::parse()**
   - 调用 `parseSelect()`
   - 输出：`SelectNode`
     - `fromTables`: `[{db:"", table:"users", alias:"u"},
                       {db:"", table:"orders", alias:"o"}]`
     - `columns`: `[{COLUMN_REF, tableAlias:"u", columnName:"name"},
                    {COLUMN_REF, tableAlias:"o", columnName:"amount"}]`
     - `where`:
       ```
       AND
       ├─ EQ
       │  ├─ COLUMN_REF(u.id)
       │  └─ COLUMN_REF(o.user_id)
       └─ GT
          ├─ COLUMN_REF(o.amount)
          └─ LITERAL(100)
       ```
     - `orderBy`: `[{tableAlias:"o", columnName:"amount", ascending:false}]`

4. **Executor::execute()**
   - 分发到 `execSelect()`

5. **Executor::execSelect()**
   1. 加载 `users` 表：
      - 检查权限：`checkPermission(session, db, "users", SELECT)`
      - 加载 schema：`tblMgr_.describeTable(db, "users")`
      - 扫描数据：`recMgr_.scan(db, "users")` → 所有 users 行
   2. 加载 `orders` 表（同上）
   3. 构建笛卡尔积：
      - 对 users 的每一行 `u_row`，对 orders 的每一行 `o_row`：
        - 创建组合行 `combined_row`:
          ```
          {
            "u.id": 1, "u.name": "Alice", "id": 1,
            "o.id": 101, "o.user_id": 1, "o.amount": 150
          }
          ```
        - 注意：`"id"` 键可能有歧义（如果两表都有 `id` 列）
   4. WHERE 过滤：
      - 调用 `ExprEvaluator::evaluate(where, combined_row)`
        - 求值 `u.id = o.user_id`：
          - 左侧：`lookupColumn("u", "id", combined_row)` → 1
          - 右侧：`lookupColumn("o", "user_id", combined_row)` → 1
          - 比较：1 == 1 → true
        - 求值 `o.amount > 100`：
          - 左侧：`lookupColumn("o", "amount", combined_row)` → 150
          - 右侧：LITERAL(100)
          - 比较：150 > 100 → true
        - AND 结果：true
      - 保留该行
   5. ORDER BY 排序：
      - 按 `o.amount` 降序排列
   6. 投影输出：
      - 提取 `u.name` 和 `o.amount` 列
      - 输出列名：`["name", "amount"]`
      - 输出行：`[["Alice", 150], ...]`

6. **返回 QueryResult**
   - `type`: SELECT
   - `columns`: `[{name:"name", type:VARCHAR}, {name:"amount", type:DOUBLE}]`
   - `rows`: `[["Alice", 150], ...]`

## 4. 前端调用指南

### 4.1 基本用法
```cpp
DBEngine engine("./data");
Session session{"sess1", "mydb", "", "root"};

std::string sql = "SELECT * FROM users";
QueryResult result = engine.execute(sql, session);

if (result.type == QueryResult::Type::ERROR) {
    // 显示错误
    std::cerr << "Error: " << result.message << std::endl;
} else if (result.type == QueryResult::Type::SELECT) {
    // 渲染表格
    for (const auto& col : result.columns) {
        std::cout << col.name << "\t";
    }
    std::cout << "\n";
    for (const auto& row : result.rows) {
        for (const auto& val : row) {
            std::cout << fieldValueToString(val) << "\t";
        }
        std::cout << "\n";
    }
}
```

### 4.2 多表查询注意事项
- 使用表别名可以避免列名歧义
- Qualified 列名（`table.column`）在 WHERE 和 SELECT 中都被支持
- ORDER BY 也支持 qualified 列名
- 如果列名有歧义且未使用 qualified 形式，SELECT / ORDER BY 会返回错误；请使用 `table.column` 或 `alias.column`

### 4.3 前端无需关心的细节
- Token 流、AST 结构
- 笛卡尔积构建算法
- 表扫描顺序
- 索引优化（未来功能）

前端只需：
1. 调用 `engine.execute(sql, session)`
2. 检查 `result.type`
3. 渲染 `result.columns` 和 `result.rows`
4. 显示 `result.message`（错误或成功消息）

## 5. 常见问题

### Q1: 多表查询性能如何？
**A**: 当前实现使用全表扫描 + 笛卡尔积 + WHERE 过滤。对于小规模数据（<1000 行/表）性能足够。大规模数据建议：
- 添加索引（已支持 CREATE INDEX）
- 使用 WHERE 条件尽早过滤
- 未来可优化为 nested loop join 或 hash join

### Q2: 如何处理列名歧义？
**A**: 使用 qualified 列名。多表 SELECT / ORDER BY 中裸列名重复时会报错：
```sql
-- Bad: 列名 id 在两个表中都存在，会报 Ambiguous column
SELECT id FROM users, orders WHERE ...

-- Good: 使用表别名限定
SELECT u.id, o.id FROM users u, orders o WHERE ...
```

### Q3: 支持哪些 JOIN 类型？
**A**: 当前支持 **隐式内连接**（逗号分隔表 + WHERE 条件）和显式 `INNER JOIN ... ON` / `JOIN ... ON`。显式连接会解析成 `TableRef.onCondition`，Executor 在构建多表组合时提前应用 ON 条件。
```sql
-- 隐式连接
SELECT * FROM users u, orders o WHERE u.id = o.user_id

-- 显式内连接
SELECT * FROM users u INNER JOIN orders o ON u.id = o.user_id
```
当前不支持 `LEFT/RIGHT/FULL OUTER JOIN`，这些外连接仍列入后续扩展。

### Q3.1: 支持 `IN (SELECT ...)` 吗？
**A**: 暂不支持。当前 `IN` 只支持字面量列表：
```sql
SELECT * FROM users WHERE id IN (1, 2, 3);
```
`WHERE id IN (SELECT user_id FROM orders)` 需要增加子查询 AST、子查询执行入口和 WHERE 集合匹配，已列入 P1 扩展。

### Q3.2: 支持存储过程或触发器吗？
**A**: 暂不支持。当前没有过程/触发器的 Lexer Token、AST 节点、系统目录元数据，也没有 `CALL` 或 DML 触发钩子。二期建议先做最小闭环：
- 存储过程：`CREATE PROCEDURE` / `CALL` / `DROP PROCEDURE`
- 触发器：AFTER INSERT / AFTER UPDATE / AFTER DELETE

### Q4: RESTORE DATABASE 如何工作？
**A**:
1. 读取备份的 SQL 文件（由 BACKUP DATABASE 生成）
2. 逐行解析 SQL 语句
3. 通过 Parser + Executor 路径执行每条语句
4. Best-effort 模式：遇到错误继续执行后续语句
5. 返回成功/失败统计

### Q5: CREATE INDEX 何时回填？
**A**: 创建索引时会自动扫描表的所有现有记录并插入索引。后续的 INSERT/UPDATE/DELETE 操作会自动维护索引。

## 6. 扩展点

未来可在以下方面扩展：
- **查询优化器**：WHERE 条件下推、索引选择、JOIN 顺序优化
- **外连接语法**：后续再做 `LEFT JOIN` / `RIGHT JOIN` / `FULL OUTER JOIN`
- **子查询**：P1 先做单列、非关联 `WHERE id IN (SELECT ...)`
- **视图**：`CREATE VIEW`
- **存储过程/函数**：P2 先做过程定义、调用和删除
- **触发器**：P2 先做 AFTER INSERT/UPDATE/DELETE 钩子
- **并发控制**：MVCC、悲观锁
