# DBMS-5 验收演示方案

## 1. 演示目标

本方案用于最终汇报和录屏复现。演示分为三条线：

| 线索 | 目标 | 证明材料 |
|---|---|---|
| SQL 功能线 | 覆盖 DDL、DML、JOIN、聚合、事务、权限、安全和索引 | `demos/full_acceptance_demo.sql` |
| Qt 界面线 | 证明普通用户能在界面完成登录、建表、插入、查询、索引和授权 | `demos/qt_admin_workflow_demo_fullscreen.mp4` |
| 实现讲解线 | 按成员任务说明关键模块如何实现 | `docs/final/DBMS-5_项目汇报.pptx` |

## 2. 演示表设计

| 表 | 字段 | 用途 |
|---|---|---|
| `users` | `uid`, `name`, `region`, `age`, `email`, `level` | 展示主键、自增、非空、唯一、默认值、ALTER TABLE、普通查询 |
| `orders` | `oid`, `user_id`, `amount`, `status` | 展示外键、订单明细、隐式 JOIN、显式 INNER JOIN、聚合分组 |
| `audit_log` | `id`, `action`, `actor` | 展示事务提交和回滚前后的数据差异 |
| `accept_reader` | 普通用户账号 | 展示 GRANT / REVOKE 后权限变化和越权拒绝 |

这三张表可以覆盖课堂验收中最容易被追问的点：结构定义、数据增删改查、联表查询、事务、安全权限、索引和界面管理。

## 3. CLI 演示顺序与结果解释

建议先启动 CLI，再执行：

```text
source demos/full_acceptance_demo.sql
```

如果需要逐句讲解，可按下面顺序复制执行。

| 段落 | 语句范围 | 实现入口 | 结果解释 |
|---|---|---|
| 1 | `CREATE DATABASE`、`CREATE TABLE`、`SHOW TABLES`、`DESCRIBE users` | `Parser::parse` 生成 DDL AST，`Executor::execCreateDatabase/execCreateTable` 调用 `DatabaseManager` 和 `TableManager` 写入结构文件 | `SHOW TABLES` 应出现 `users`、`orders`；`DESCRIBE users` 应显示 `uid` 主键自增、`name` 非空、`email` 唯一、`region/age` 默认值 |
| 2 | `INSERT`、`SELECT`、`WHERE`、`ORDER BY`、`LIMIT` | `Executor::execInsert/execSelect` 完成权限检查、约束检查、记录扫描和 `ExprEvaluator` 条件求值 | 全量查询应出现 Alice、Bob、Cindy；条件查询只保留 `age >= 28` 的记录，并按年龄倒序取前 2 条 |
| 3 | `INNER JOIN ... ON`、`GROUP BY`、`HAVING`、`SUM/COUNT` | `Parser` 保存 `TableRef`、别名和 ON 条件，`Executor::execSelect` 组合多表行并执行分组聚合 | JOIN 结果把用户和订单按 `u.uid = o.user_id` 对齐；聚合结果按 `region` 汇总订单数和金额，`HAVING` 过滤不满足数量的分组 |
| 4 | `UPDATE`、`DELETE`、`ALTER TABLE`、`CREATE INDEX` | `Executor::execUpdate/execDelete/execAlterTable/execCreateIndex` 修改记录和表结构，`IndexManager` 调用 `BTreeIndex` 回填已有记录 | Alice 的年龄和地区被更新；低金额订单被删除；`DESCRIBE users` 增加 `level` 字段；索引创建返回 backfilled 结果 |
| 5 | `BEGIN`、`ROLLBACK`、`COMMIT` | `TransactionManager` 记录 Undo Log，`WalManager` 记录事务状态，回滚时按旧值恢复 | `ROLLBACK` 后 Bob 年龄仍为 25；`COMMIT` 后高金额订单状态保持为 `archived` |
| 6 | `CREATE USER`、`GRANT`、普通用户 `SELECT`、普通用户 `INSERT` | `UserManager` 保存用户和权限，`Executor::checkPermission` 在执行前统一拦截 | `cli_reader` 只能查询 `cli_demo.users`；未授权 `INSERT` 返回权限错误，证明安全逻辑在后端生效 |
| 7 | `DROP USER`、`DROP DATABASE` | `Executor` 调用用户和数据库管理模块清理演示环境 | 删除临时用户和数据库，保证脚本可以反复运行 |

## 4. Qt 录屏脚本

现有录屏入口为：

```powershell
.\run_qt.bat
```

录屏建议按下面镜头组织：

| 镜头 | 操作 | 要说明的实现点 |
|---|---|---|
| 1 | root/root 登录，刷新对象树 | `SessionPanel` 发出登录请求，`QtSessionAdapter` 调用 `CONNECT` |
| 2 | 创建 `qt_demo_video.products` | Admin 面板把字段表格转换成 `CREATE TABLE` |
| 3 | 插入并查询商品数据 | SQL 编辑器与表格编辑都统一走 `DBEngine::execute()` |
| 4 | 添加列、创建索引 | Structure / Object 页生成 `ALTER TABLE` 和 `CREATE INDEX` |
| 5 | 表格新增一行并保存 | `TableEditorPanel` 生成 `INSERT / UPDATE / DELETE` |
| 6 | 创建普通用户并授予 SELECT | Users 页生成 `CREATE USER` 和 `GRANT` |
| 7 | 切换普通用户查询成功、写入失败 | 权限不是 UI 判断，而是 Executor 统一拦截 |

## 6. 现场注意事项

- 演示前先确认 `data/` 中没有同名残留库；脚本开头包含 `DROP DATABASE IF EXISTS dbms5_demo`，可重复执行。
- 权限演示中，普通用户执行 `INSERT` 和 `SELECT * FROM orders` 预期失败，这是安全功能的证明，不是演示错误。
- 如果现场时间有限，CLI 只展示 DDL、JOIN、事务、权限四段；完整覆盖由脚本和测试报告补充。
- PPT 中成员页按“负责模块 → 实现方法 → 演示证据”讲，不只说分工。
