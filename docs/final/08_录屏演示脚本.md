# DBMS-5 录屏演示脚本

## 1. 录屏目标

本录屏用于最终验收展示，建议控制在 8-12 分钟。内容按“先证明完整 SQL 能力，再证明 Qt 界面可操作，最后回到实现亮点”组织。

录屏主线：

1. 项目简介：说明 DBMS-5 是 C++17 自研轻量级关系型数据库。
2. CLI 全功能演示：用固定脚本覆盖 DDL、DML、JOIN、聚合、索引、事务、权限。
3. Qt 界面演示：展示登录、建表、插入、查询、索引、权限管理。
4. 实现总结：说明所有入口统一调用 `DBEngine::execute()`，不是前后端各做一套逻辑。

## 4. CLI 全功能演示

建议时长：4-6 分钟。

### 4.1 启动 CLI 并执行脚本

屏幕操作：

```powershell
.\build-windows\dbms.exe
```

进入 `dbms>` 后输入：

```text
source demos/full_acceptance_demo.sql
```

旁白：

> 这里通过 source 执行完整验收脚本。脚本会自动登录 root，创建演示数据库 `dbms5_demo`，并创建 `users`、`orders`、`audit_log` 三张表。  
> 这三张表分别用于展示用户信息、订单联表查询，以及事务提交和回滚。

### 4.2 DDL 与约束

观察输出：

- `Database 'dbms5_demo' created`
- `Table 'users' created`
- `Table 'orders' created`
- `DESCRIBE users`

旁白：

> 第一段展示 DDL。`users` 表包含主键、自增、非空、唯一和默认值；`orders` 表通过外键引用 `users.uid`。  
> 这些结构会由 Parser 解析成 AST，再由 Executor 调用 TableManager 和 RecordManager 写入表结构和数据文件。

重点语句：

```sql
CREATE TABLE users (
    uid INTEGER PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(40) NOT NULL,
    region VARCHAR(20) DEFAULT 'unknown',
    age INTEGER DEFAULT 0,
    email VARCHAR(80) UNIQUE
);
```

```sql
CREATE TABLE orders (
    oid INTEGER PRIMARY KEY AUTO_INCREMENT,
    user_id INTEGER,
    amount DOUBLE NOT NULL,
    status VARCHAR(20) DEFAULT 'new',
    CONSTRAINT fk_orders_user FOREIGN KEY (user_id) REFERENCES users(uid)
);
```

### 4.3 DML 查询

观察输出：

- 插入 `Alice`、`Bob`、`Cindy`
- `SELECT * FROM users`
- `WHERE age >= 28`
- `DISTINCT region`

旁白：

> 第二段展示 DML。系统支持插入、查询、条件过滤、排序、限制行数和 DISTINCT 去重。  
> 查询执行时会先检查权限，再扫描记录文件，使用 ExprEvaluator 计算 WHERE 条件，最后把列名和行数据封装成 QueryResult。

重点语句：

```sql
SELECT name, region, age
FROM users
WHERE age >= 28
ORDER BY age DESC
LIMIT 2;
```

### 4.4 联表查询与聚合

观察输出：

- `Bob 320.5 paid`
- `Alice 199.99 paid`
- `East order_count 3 total_amount 332.99`

旁白：

> 第三段是联表查询。我们同时演示了逗号 FROM 的隐式内连接，以及标准的 `INNER JOIN ... ON` 写法。  
> Parser 会记录表别名和连接条件，Executor 对多表记录进行组合，再用 ExprEvaluator 判断 `u.uid = o.user_id` 这样的列间比较。  
> 后面的 GROUP BY、HAVING 和 SUM/COUNT 证明系统不只是能查单表，也能做分组聚合。

重点语句：

```sql
SELECT u.name, o.amount, o.status
FROM users u, orders o
WHERE u.uid = o.user_id AND o.amount > 100
ORDER BY o.amount DESC;
```

```sql
SELECT u.region, COUNT(o.oid) AS order_count, SUM(o.amount) AS total_amount
FROM users u INNER JOIN orders o ON u.uid = o.user_id
GROUP BY u.region
HAVING COUNT(o.oid) >= 2
ORDER BY total_amount DESC;
```

### 4.5 UPDATE、DELETE、ALTER 与索引

观察输出：

- Alice 的 `age` 和 `region` 变化
- 金额小于 50 的订单被删除
- `DESCRIBE users` 中出现 `level`
- 索引创建和回填成功

旁白：

> 接下来演示 UPDATE、DELETE、ALTER TABLE 和 CREATE INDEX。  
> ALTER TABLE 会更新表结构并迁移记录布局；CREATE INDEX 会把已有记录回填进索引。项目中索引由 `IndexManager` 管理，底层使用 `BTreeIndex` 维护键到记录偏移的映射。

重点语句：

```sql
UPDATE users SET age = 31, region = 'North' WHERE name = 'Alice';
DELETE FROM orders WHERE amount < 50;
ALTER TABLE users ADD COLUMN level VARCHAR(20) DEFAULT 'normal';
CREATE INDEX idx_orders_user_status ON orders(user_id, status);
```

### 4.6 事务提交与回滚

观察输出：

- `ROLLBACK` 后 Bob 年龄仍为 25
- `ROLLBACK` 后 `audit_log` 为空
- `COMMIT` 后 `audit_log` 中保留 `commit-change`
- 金额大于 300 的订单状态变为 `archived`

旁白：

> 这一段演示事务。第一组事务插入日志并修改 Bob 年龄，但执行 ROLLBACK 后所有变化都被撤销。  
> 第二组事务执行 COMMIT，所以日志和订单状态会保留下来。  
> 运行时回滚依靠 Undo Log；如果进程异常退出，则由 WAL 在下次启动时做恢复。

重点语句：

```sql
BEGIN;
INSERT INTO audit_log (action, actor) VALUES ('temporary-change', 'demo');
UPDATE users SET age = 99 WHERE name = 'Bob';
ROLLBACK;
```

```sql
BEGIN;
INSERT INTO audit_log (action, actor) VALUES ('commit-change', 'demo');
UPDATE orders SET status = 'archived' WHERE amount > 300;
COMMIT;
```

### 4.7 权限安全

观察输出：

- `accept_reader` 查询 `users` 成功
- `accept_reader` 插入 `users` 失败
- `REVOKE` 后查询 `orders` 失败

旁白：

> 最后是权限安全演示。root 创建普通用户 `accept_reader`，只授予 SELECT 权限。  
> 因此普通用户可以查询被授权的表，但不能 INSERT。随后 root 回收 orders 表的 SELECT 权限，普通用户再次查询 orders 会失败。  
> 这里的红色 ERROR 是预期结果，说明权限检查在 Executor 层生效，而不是 UI 层简单隐藏按钮。

重点语句：

```sql
CREATE USER 'accept_reader' IDENTIFIED BY 'reader123';
GRANT SELECT ON dbms5_demo.users TO 'accept_reader';
GRANT SELECT ON dbms5_demo.orders TO 'accept_reader';
```

```sql
INSERT INTO users (...) VALUES (...);
-- 预期失败：缺少 INSERT 权限
```

```sql
REVOKE SELECT ON dbms5_demo.orders FROM 'accept_reader';
SELECT * FROM orders;
-- 预期失败：SELECT 权限已被回收
```

## 5. Qt 界面演示

建议时长：3-5 分钟。

### 5.1 启动 Qt

屏幕操作：

```powershell
.\run_qt.bat
```

旁白：

> 接下来演示 Qt 图形界面。Qt 并不直接读写数据文件，也不重新实现 SQL 解析，而是通过 `QtSessionAdapter` 调用同一个 `DBEngine::execute()`。

### 5.2 登录与对象树

屏幕操作：

1. 用户名输入 `root`。
2. 密码输入 `root`。
3. 点击连接。
4. 查看左侧数据库、表、列、索引和用户树。

旁白：

> 登录后，左侧对象树会刷新数据库、表、列、索引和用户信息。这个目录来自后端查询结果，而不是界面硬编码。

### 5.3 创建演示库和表

屏幕操作：

可以在 SQL 编辑区执行：

```sql
DROP DATABASE IF EXISTS qt_demo_video;
CREATE DATABASE qt_demo_video;
USE qt_demo_video;
```

然后在 Admin 面板中创建 `products` 表：

| 字段 | 类型 | 约束 |
|---|---|---|
| `id` | `INT` | PRIMARY KEY |
| `name` | `VARCHAR(40)` | NOT NULL |
| `stock` | `INT` |  |

旁白：

> Admin 面板把字段表格转换成 CREATE TABLE 语句，再交给后端执行。这样用户不用手写完整 DDL，也能完成建表。

### 5.4 插入和查询

屏幕操作：

在 SQL 编辑区执行：

```sql
INSERT INTO products (id, name, stock) VALUES (1, 'keyboard', 12);
INSERT INTO products (id, name, stock) VALUES (2, 'mouse', 34);
SELECT id, name, stock FROM products ORDER BY id;
```

旁白：

> SQL 编辑器直接发送 SQL，结果显示在 Query Result 表格中。后端返回的 QueryResult 会被 Qt 渲染成表格。

### 5.5 表结构和索引

屏幕操作：

1. 在 Admin / Structure 中给 `products` 添加 `note VARCHAR(60)`。
2. 创建索引：

```text
idx_products_name
```

字段：

```text
name
```

旁白：

> 这里演示 ALTER TABLE 和 CREATE INDEX。添加列后对象树会刷新，创建索引后可以在树中看到索引节点。

### 5.6 表格编辑

屏幕操作：

在 Table Data 页新增一行：

| id | name | stock |
|---|---|---|
| 3 | monitor | 8 |

点击保存，再查询：

```sql
SELECT id, name, stock FROM products ORDER BY id;
```

旁白：

> Table Data 页不是直接改文件，而是把新增、修改、删除转换为 INSERT、UPDATE、DELETE。权限、类型和约束仍然由后端判断。

### 5.7 权限管理

屏幕操作：

1. 在 Admin / Users 中创建用户：

```text
demo_reader / reader123
```

2. 对 `qt_demo_video.products` 勾选 SELECT，点击授权。
3. 切换登录到 `demo_reader / reader123`。
4. 执行：

```sql
USE qt_demo_video;
SELECT name, stock FROM products WHERE stock > 10;
INSERT INTO products (id, name, stock) VALUES (9, 'blocked', 1);
```

旁白：

> 普通用户被授予 SELECT 后可以查询，但没有 INSERT 权限，所以插入失败。这个失败是预期的安全验证。
